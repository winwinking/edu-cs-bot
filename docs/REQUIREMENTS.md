教育平台高并发 AI 客服机器人后端系统的构建与测试
一、题目背景
某在线教育平台需要一个面向学员、家长的智能客服机器人。用户通过平台 IM 与机器人沟通，机器人需要完成以下四类核心任务：

1. 平台客户端指令运行：如关闭自动续费、修改提醒、打开课程表、提交请假、转接人工等。
2. 知识问答：基于平台课程、退费、活动、服务协议、常见问题等知识库回答。
3. 日程安排和提示：创建、修改、取消提醒，按时通过 IM 推送。
4. 财务数据调取和回复：查询订单、账单、发票、退费进度、余额等，但必须严格权限校验和脱敏。

同时，系统有较高并发要求：消息入口可能面对突发流量，机器人回复需要稳定、可降级、可观测。机器人语言必须专业、人性化、少 AI 味，不能像通用大模型一样堆砌套话。

你需要以后端工程师身份，从零构建一套可运行、可测试、可压测、可演示的 AI 应用系统后端。允许并鼓励使用 coding agent 工具辅助开发，但必须提交 agent 使用记录，并能解释、修改、排障你提交的代码。

---

二、候选人任务

构建一个多租户教育平台客服机器人后端系统，至少包含以下能力：

· IM 消息接入与回复
· 会话上下文管理
· 意图识别与任务路由
· LLM/RAG 知识问答
· 工具调用与平台指令执行
· 日程提醒与延迟推送
· 财务数据查询与脱敏回复
· 人工转接
· 高并发、限流、熔断、降级、幂等
· 安全、审计、可观测
· 自动化测试与压测报告

技术栈不限，但必须 Docker Compose 一键启动。可使用 Python/FastAPI、Go/Gin、Node/NestJS、Java/Spring Boot 等。数据库、缓存、队列、向量库可自选，但必须容器化。

三、功能需求

FR-1 IM 接入与会话

· 支持 WebSocket 或 HTTP Webhook 接入 IM 消息。
· 支持消息去重、幂等、ACK、断线重连、多端同步。
· 每个会话保存上下文，支持短期记忆与历史摘要。
· 支持多租户隔离，不同教育机构/校区数据不能串。
· 支持流式回复，首 token 尽量快。

FR-2 意图识别与路由

机器人需识别并路由到：

· 平台指令
· 知识问答
· 日程提醒
· 财务查询
· 闲聊/安抚
· 转人工
· 高风险/敏感操作

要求：

· 意图识别可基于规则、LLM 或混合方案。
· 工具调用参数必须经过 JSON Schema 校验。
· LLM 输出不能直接执行，必须有安全校验。

FR-3 平台客户端指令运行

示例指令：

· 关闭/开启自动续费
· 修改课程提醒
· 打开课程表
· 提交请假
· 查询学习报告
· 转接人工

要求：

· 执行前进行权限校验。
· 高风险指令必须二次确认。
· 指令下发到 mock 平台客户端，支持超时、重试、幂等。
· 返回结果要转化为自然、专业、少 AI 味的客服话术。

FR-4 知识问答

· 基于平台知识库进行 RAG 检索。
· 回答必须尽量给出依据来源。
· 无依据时不能编造，应回答“我暂时没有查到明确依据，建议转人工确认”。
· 支持多轮澄清。
· 支持知识库更新后重新索引。

FR-5 日程安排和提醒

· 创建、修改、取消提醒。
· 支持时区，如 Asia/Shanghai。
· 支持重复规则，如每天、每周、工作日。
· 到点后通过 IM 推送。
· 支持提前提醒，如提前 30 分钟。
· 提醒任务持久化，服务重启不丢。

FR-6 财务数据调取和回复

· 查询订单、账单、发票、退费进度、余额。
· 必须校验 tenant_id、user_id、权限。
· 敏感信息脱敏，如邮箱、手机号、银行卡、身份证。
· 财务系统超时或失败时，不能编造数据。
· 回复示例：
  · “我查到 2024-05 有一笔订单 #EDU-20240512-8831，金额 ¥2,399，发票状态：已开具，电子发票已发送到 l***@example.com。需要我重发吗？”
· 所有财务查询写入审计日志。

FR-7 人工转接

· 用户说“转人工”或连续两次不满意时触发。
· 转接时携带会话摘要、用户意图、已尝试操作、风险提示。
· 人工坐席不在线时，给出明确等待或留言方案。

FR-8 语言风格

机器人语言要求：

· 专业、简洁、有人情味。
· 少 AI 味：不用“作为 AI”“我很乐意”“总之”“希望对你有帮助”等套话。
· 不堆砌表情，不强行卖萌。
· 先确认问题，再给结论，再给下一步。
· 不确定时明确说不确定，并给转人工或稍后回复方案。
· 高风险操作必须确认。
· 示例：
  · 用户：“我下个月想续费，但最近手头紧，能先停掉自动扣款吗？”
  · 机器人：“可以的。我先帮你确认：你要关闭的是‘春季数学班’的自动续费，对吗？关闭后不影响已购课程，本月已排课程照常上。回复‘确认关闭’我就处理。”

四、非功能需求

NFR-1 高并发

· 支持水平扩展，应用服务尽量无状态。
· 消息入口与 LLM/工具调用异步解耦。
· 使用消息队列削峰。
· 支持限流、熔断、降级、重试、死信队列。
· 目标压测指标：
  · 500 并发 WebSocket 连接。
  · 持续 5 分钟，每秒 200 条消息。
  · 入站 ACK P95 < 300ms。
  · 首响 P95 < 1.5s。
  · 完整回复 P95 < 3s，使用 mock LLM。
  · 错误率 < 1%。
  · 突发 1000 msg/s 持续 30s，不丢消息，恢复后能处理。

NFR-2 可靠性

· 消息至少一次投递，业务幂等。
· 财务、指令、提醒操作可追踪。
· 服务重启后提醒不丢。
· LLM 超时、财务系统 500、Redis 故障时能降级。

NFR-3 安全

· 多租户隔离。
· JWT/OAuth2 或等价鉴权。
· RBAC 权限控制。
· 敏感字段脱敏。
· 防 Prompt Injection、SQL 注入、越权查询。
· 日志不得记录完整身份证、银行卡、密码、token。
· 密钥不得提交到仓库。

NFR-4 可观测

· 结构化日志，带 trace_id、tenant_id、conversation_id。
· Prometheus 指标：QPS、延迟、错误率、队列积压、LLM token、工具成功率。
· 关键链路追踪。
· 审计日志：谁在何时查询了谁的财务数据、执行了什么指令。

NFR-5 成本与评测

· 记录 LLM token 消耗，按租户统计。
· 支持模型路由或降级。
· 提供离线评测集，评估事实准确性、引用、语气、少 AI 味。

五、运行环境

候选人需提供 Docker Compose 一键启动环境，至少包含：

· 应用服务
· PostgreSQL 15
· Redis 7
· 消息队列：NATS JetStream / RabbitMQ / Kafka 任选
· 向量库：Qdrant / pgvector / Milvus 任选
· Mock 服务：
  · mock-im
  · mock-llm
  · mock-knowledge
  · mock-platform
  · mock-finance

硬件建议：

· 8 核 CPU
· 16GB 内存
· 50GB 磁盘
· Linux/macOS + Docker 24+ + Docker Compose v2

端口约定可自定，但需在 README 说明。必须提供：

· make up
· make test
· make loadtest
· make demo
· .env.example
· 数据库迁移脚本
· 健康检查接口

不得依赖真实付费 LLM、真实财务系统、真实 IM 作为测试必选。可以使用真实 LLM 做演示，但自动化测试必须使用 mock。

六、测试要求

6.1 单元测试

· 核心模块覆盖率 ≥ 70%。
· 覆盖意图路由、权限校验、幂等、脱敏、日程规则、工具参数校验。

6.2 集成测试

· 使用 Testcontainers 或 Docker Compose 启动依赖。
· 覆盖 IM 入站、队列、LLM mock、知识检索、财务 mock、提醒调度。

6.3 端到端测试

必须覆盖以下场景：

1. 用户查询课程政策，机器人引用知识库回答。
2. 用户查询发票，机器人返回脱敏结果。
3. 用户 A 查询用户 B 财务，返回 403。
4. 用户关闭自动续费，机器人二次确认后执行。
5. 用户创建“明天 9 点提醒”，到点后 5 秒内推送。
6. 用户说“转人工”，携带摘要转接。
7. 财务系统超时，机器人不编造，回复“暂时查不到，已记录，稍后回复”。
8. LLM 返回非法 JSON，系统兜底，不执行工具。
9. 重复 message_id 只处理一次。
10. 知识库无命中，机器人不瞎编，建议转人工。

6.4 压测要求

· 提供 k6 / Locust / wrk 脚本。
· 提供压测报告：QPS、P50/P95/P99、错误率、队列积压、CPU/内存。
· 场景：
  · 稳定 200 msg/s，持续 5 分钟。
  · 突发 1000 msg/s，持续 30 秒。
  · 财务查询 100 QPS，P95 < 500ms。
  · LLM 超时率 20% 时，系统降级且不崩溃。

6.5 故障注入

· mock-llm 延迟 5s / 返回 500 / 返回幻觉内容。
· mock-finance 超时 / 500。
· Redis 重启。
· 队列积压。
· 验证熔断、降级、重试、死信、告警。

6.6 LLM 质量评测

· 提供 50 条固定测试集。
· 指标：
  · 事实准确率
  · 引用命中率
  · 越权拒绝率
  · 少 AI 味评分
  · 转人工准确率
· 少 AI 味评分标准：
  · 不出现“作为 AI”“我很乐意”“总之”等。
  · 不堆砌客套话。
  · 给出具体步骤、时间、状态。
  · 不确定时明确说明。

七、负面清单

出现以下情况将明显扣分或直接淘汰：

安全类

· 硬编码 API Key、数据库密码、token。
· 日志打印完整身份证、银行卡、手机号、密码。
· 不做租户隔离。
· 不做权限校验，允许越权查询财务。
· 把用户输入直接拼进系统提示，导致 Prompt Injection。
· LLM 输出未经校验直接执行工具。
· 高风险操作无二次确认。

工程类

· 只做单机 demo，无队列、无限流、无熔断。
· 同步阻塞调用 LLM，导致吞吐极低。
· 无限重试，导致雪崩。
· 消息重复处理，财务/指令重复执行。
· 服务重启后提醒丢失。
· 无健康检查、无迁移、无 README。
· 测试依赖真实外部付费服务。

AI 类

· 财务、政策问题无依据编造。
· 知识库无命中仍强行回答。
· 机器人语言充满 AI 味。
· 不记录 token 成本。
· 不区分意图，所有问题都直接丢给 LLM。

提交类

· 只交视频/截图，不交源码。
· 提交仓库包含 .env、密钥、真实用户数据。
· 使用 coding agent 生成后完全不审查，无法解释代码。
· 抄袭开源项目但不说明来源和改动。
· 无测试、无压测、无评测报告。

附录 A：示例对话

知识问答

用户：寒假班请假会退课时费吗？
机器人：根据《课程服务协议》第 4.2 条，寒假班请假需提前 24 小时在小程序提交，未消耗课时可顺延；若未提前提交，该课时按已消耗处理。退费规则和普通班不同，我可以帮你查具体订单是否符合。

财务查询

用户：我上个月的发票开了吗？
机器人：我查到 2024-05 有一笔订单 #EDU-20240512-8831，金额 ¥2,399，发票状态：已开具，电子发票已于 5 月 18 日发送到 l***@example.com。需要我重发吗？

日程提醒

用户：帮我把明天 19:00 的家长会提醒打开。
机器人：已设置提醒：明天 19:00，提前 30 分钟在 IM 通知你。需要同时短信提醒吗？

高风险指令

用户：帮我把自动续费关了。
机器人：我先确认一下：你要关闭的是“春季数学班”的自动续费，对吗？关闭后不影响已购课程，本月已排课程照常上。回复“确认关闭”我就处理。

附录 B：少 AI 味风格指南

推荐：

· “我查到……”
· “我先帮你确认……”
· “这一步需要你确认后我才操作。”
· “目前系统暂时查不到，我先记录，稍后人工回复你。”
· “你可以回复‘确认关闭’，我就处理。”

禁止或慎用：

· “作为 AI 助手……”
· “我很乐意为你服务……”
· “总之，希望对你有所帮助。”
· “亲亲，不要着急哦～”
· 大段免责声明。
· 没有信息量的重复道歉。

附录 C：Mock 服务建议契约

· mock-im：WebSocket 收发消息，支持在线状态、已读、断线重连。
· mock-llm：/v1/chat/completions，支持流式、延迟、错误率、幻觉注入。
· mock-knowledge：/search?q=，返回片段、来源、score。
· mock-platform：/commands，接收指令，返回 command_id、status、result。
· mock-finance：/orders、/invoices、/refunds，校验 tenant_id、user_id、token，支持越权测试。
